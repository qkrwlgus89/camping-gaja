# 캠핑가자 v1.2.0 검증 기록

검증일: 2026-11-18 KST. 이번 변경은 기존 공동 캠핑장/4인 텐트 위에 해먹, 좌석 점유, 다양한 SD 아바타, 공동 바베큐, 불돌기, 작은 닉네임/말풍선, 버튼 포커스 수정, 실제 태양과 노을을 추가했습니다. 비공개 2인 기획보다 사용자의 후속 요청을 우선했습니다. 9번 빈 항목은 구현 범위에 넣지 않았습니다.

## 환경과 결과

- Node.js 24.14.1, Next.js 16.4.6, React 19.3.1, R3F 9.8.2, Three.js 0.187.0.
- `NEXT_PUBLIC_ENABLE_SCENE_LAB=true npm run build` 후 `ENABLE_LOCAL_DEMO=true npm start -- --port 3001`로 최종 프로덕션 버전을 실행했습니다.
- 설치된 Chrome 157.0.8103.79, Playwright 1.65.1, headless ANGLE/SwiftShader WebGL2. 모바일 대체 환경은 세로 360×800 / 가로 800×360, 터치 에뮬레이션·CDP 터치, DPR 2입니다.

- SQL은 localhost PostgreSQL 18에 임시 DB를 만들고 세 마이그레이션을 실제 적용했습니다. Supabase auth/realtime 함수·역할은 최소 stub이며 테스트 DB는 삭제합니다.

## 성능과 미확인 항목

해상도 수정 전의 [성능 샘플](performance.json)은 모바일 360×800, 10Mbps down/5Mbps up/80ms, 캐시 비활성화·SwiftShader에서 측정했습니다. 첫 스틸 준비 438ms, FCP 808ms, WebGL 준비 1,987ms, 전송 2,747,879바이트, 걷기 30.8FPS, 자동 DPR 0.55입니다. 단일 소프트웨어 렌더러 샘플이며 휴대폰 GPU의 FPS·발열·입력 지연을 보장하지 않습니다.

실제 휴대폰/iOS Safari, 실제 Supabase GoTrue·Broadcast 지연/동시접속 부하, 기상청 실키, 새 마이그레이션이 적용된 Vercel Preview/운영은 확인하지 않았습니다. 로컬 공유 검사는 단일 프로세스 HTTP 어댑터이며 실제 WebSocket 검증과 구별합니다. 실제 모바일 청음·공유 시트/사진 저장도 미확인입니다.

여러 광장으로 나누는 운영은 범위 밖입니다. 기본 8개 텐트에 점유 텐트를 더해 최대 24개, 화면의 상대 아바타는 최대 32개입니다. 그래픽은 실시간 경량 절차적 장면이며 미술 품질은 스크린샷과 직접 조작으로 검토했습니다.

GitHub commit/push, 운영 SQL 실행, Vercel 배포는 수행하지 않았습니다. 배포 전 신규 social 마이그레이션을 적용하고 README의 명령을 사용하세요.

## 아바타 후속 수정

보류했던 외형 수정을 사용자의 재개 요청에 따라 반영했습니다. 얼굴은 둥근 타원 메시, 뒷머리 고리와 머리끈 장식은 제거, 기본 팔 길이는 약 23% 줄이고 몸 옆으로 펴는 자세로 변경했습니다. 걷기 때 작은 앞뒤 흔들림, 앉을 때 앞으로 내리는 자세와 손 인사/먹기/손잡기는 유지합니다.

짧은 팔에 맞춘 원형 반지름은 `max(0.86, 1.14 / (2 * sin(pi / n)))`, 손 높이는 0.62m입니다. WebGL 좌표 검사에서 의자 8종 골반 접점 모두 0.5475m, 해먹 2종 등 접점 0.64m, 4인 손목 오차 최대 1.65mm·5~8인 사실상 0을 확인했습니다. [최신 좌표 결과](avatar-round-results.json), [앞모습](avatar-round-front.png), [뒷모습](avatar-round-back.png), [앉기](avatar-round-seat.png), [손잡기](avatar-round-hands.png)를 참고하세요. 이전 아바타 수치/그림은 초기 v1.2 검증 자료입니다.

후속 검증은 타입 검사·단위 24개·프로덕션 빌드와 아바타에 관련된 브라우저 시나리오에 한정했습니다. 실제 기기와 배포 검증은 수행하지 않았습니다.

해먹의 상단 중앙 안내 박스를 제거하고 85.6×44px `일어나기` 버튼만 하단 왼쪽에 배치했습니다. PC 1440×900 WebGL과 모바일 360×800 스틸 대체 환경에서 버튼 위치·터치 크기·일어나기 동작을 확인했습니다. [PC](sky-unobstructed-desktop.png), [모바일](sky-unobstructed-mobile.png). 이동키/Esc 종료도 유지합니다.

말풍선 후속 수정: 고정 190×67px 패널 대신 글 길이와 실제 줄 수에 맞춰 크기를 계산합니다. 짧은 `gg`는 약 42×40px, 긴 문장은 최대 3줄과 말줄임표를 사용합니다. 글자는 중앙 정렬, 작은 꼬리는 머리 위 또는 닉네임 바로 위에 배치하고 8초 후 부드럽게 사라집니다. PC 1440×900 / 모바일 360×800 Chrome SwiftShader WebGL에서 짧은 말·긴 한국어·만료를 확인했고 페이지 오류가 없었습니다. [짧은 말](bubble-short-desktop.png), [모바일 긴 말](bubble-long-mobile.png). 타입 검사와 프로덕션 빌드도 통과했습니다.

모임 대기 겹침 수정: 참가자 모두를 `(0, 6)`으로 보내던 처리를 제거했습니다. 모집 중에는 참가 순서에 따라 1.2m 간격의 고정 대기 자리를 배정하며, 상대 위치도 공통 참가자 목록에서 계산합니다. 새 참가자가 와도 기존 대기 자리는 유지됩니다. 시작하면 기존 원형 모임 자리로 전환합니다. 1~8명 대기 자리의 간격·이동 가능 영역·의자와의 거리 단위 검사, 독립 4세션 대기 위치·모집 중 재접속·시작·종료 브라우저 검사를 통과했습니다. 전체 단위 25개와 프로덕션 빌드 통과. [대기 화면](circle-waiting-separated.png).


## 수동 즉시 시작과 그래픽 해상도 후속 수정

강강술래는 네 명이 모여도 모집 상태로 유지하며, 모집자의 `강강술래 시작` 버튼으로만 시작합니다. 서버도 즉시 active로 전환하고 60초를 공유합니다. 회전은 0.22→0.4rad/s(약 1.8배), 한 바퀴 약 15.7초이며 보행 모션도 빠르게 맞췄습니다. 실제 배포에는 새 `202611180002_manual_circle.sql` 적용이 필요합니다. 기존 세 SQL은 변경하지 않았습니다.

화질 저하 원인은 렌더 해상도가 0.55배까지 내려간 후 복구되지 않던 단방향 자동 조절입니다. 자동은 최저 1배, PC 최대 1.75배·모바일 최대 1.5배로 변경했습니다. 초기 로딩 12초와 순간 저하를 제외하고, 지속 저하 시만 낮추며 지속 회복 시 다시 높입니다. 선명하게는 PC 최대 2배·모바일 최대 1.75배로 고정하고 새로고침 후에도 보존합니다. 가볍게는 명시적으로 선택하는 0.85배입니다. 지면 이방성 필터 최대 8, PC 그림자 2048도 적용했습니다.

단위 29개·DB 49개·프로덕션 빌드를 통과했습니다. Chrome SwiftShader, DPR 2에서 실제 버퍼/CSS 비율이 PC 자동 1.75·가볍게 0.85·선명하게 2, 모바일 세로 선명하게 1.75임을 확인했습니다. 선명하게가 14초 후에도 유지되고, 설정이 새로고침 후 유지됨을 확인했습니다. 자동 모드 최저치와 회복은 시뮬레이션 단위 검사로 검증했습니다. [가볍게](graphics-light.png), [선명하게](graphics-sharp.png), [모바일 세로](graphics-mobile-sharp.png). 실제 GPU의 FPS·발열은 검증하지 않았으며 이전 성능 수치를 새 화질의 성능으로 해석하지 않습니다.

후속 브라우저 2개 시나리오(실제 렌더 버퍼/설정 유지, 네 세션 수동 즉시 시작)가 통과했고, 마지막 시간 표시 수정 후 수동 시작을 다시 확인했습니다. [후속 결과](manual-start-quality-results.json).
